# Validation Report

Generated by running `pytest validation/ -m slow -s` (see
`scripts/run_validation_suite.sh`). Every number below was measured by
running the suite after the fixes recorded in `docs/REVIEW.md`, not asserted
from theory.

## 1. CI Coverage (`raw_ttest_ci`)

**Target:** 93%–97% (nominal 95%).

| Configuration | Simulations | Coverage |
|---|---|---|
| n=2000, baseline=0.10, effect=+0.02 | 1000 | **94.4%** (944/1000) |
| n=400, baseline=0.10, effect=+0.02 | 500 | **94.4%** (472/500) |
| n=2000, baseline=0.02, effect=+0.01 | 500 | **95.0%** (475/500) |
| n=2000, baseline=0.90, effect=−0.02 | 500 | **95.4%** (477/500) |

The 94.4% at 1000 simulations is ~0.8 SE below nominal (binomial SE ≈
0.73pp) — consistent with noise. Welch's df approximation holds at small n
and near both probability boundaries.

## 2. CUPED Variance Reduction

**Target:** variance reduction ≈ 100·ρ².

| Scenario | Measured | Theory |
|---|---|---|
| ρ=0.3, null effect (200 sims, n=5000) | **9.21%** (SE 0.073) | 9.0% |
| ρ=0.7, null effect (200 sims, n=5000) | **48.67%** (SE 0.143) | 49.0% |
| ρ=0.5, true effect +0.02 | **23.87%** | 25.0% |
| ρ=0.6, continuous metric | **35.94%** (SE 0.104) | 36.0% |

The ρ=0.3 result sits ~2.9 SE above theory, most likely from the binary
outcome and right-skewed covariate rather than a bug (the continuous-metric
case matches to within 1 SE). The ~1pp shortfall under a nonzero effect
comes from how the effect is applied (additive, clipped), documented in the
validation file.

## 3. Sequential Testing — Peeking Inflation and Correction

**Configuration:** 2000 null-effect simulations (SE ≈ 0.5pp), 10
checkpoints of 200 users per arm (cumulative 200–2000), seed=2024 for both
runs (common random numbers).

| Rule | Empirical FPR | Target |
|---|---|---|
| Naive, flat α=0.05 at every look | **19.95%** (399/2000) | ~19.3% theoretical |
| O'Brien-Fleming, calibrated c=2.0865 | **5.15%** (103/2000) | 5% (band 3.5%–7%) |
| Irregular spacing, naive | **20.45%** (409/2000) | — |
| Irregular spacing, corrected | **4.80%** (96/2000) | must beat naive |
| Lan-DeMets, equal spacing | **5.25%** (105/2000) | 5% (band 3.5%–7%) |
| Lan-DeMets, irregular spacing | **5.05%** (101/2000) | 5% (band 3.5%–7%) |

**Trigger positions** (checkpoints 1→10): naive
`(89, 75, 47, 50, 29, 23, 30, 18, 24, 14)` — front-loaded on early-look
noise; corrected `(0, 0, 1, 1, 5, 12, 17, 23, 19, 25)` — essentially never
at the first looks, concentrated late.

**History:** an earlier version used c = 1.96 (full nominal α at the final
look), whose exact type-I error is ~6.9%. It measured 6.6% at 500
simulations — too few to distinguish 5% from 7% — and was accepted against
a band widened to 7.5%. See `docs/REVIEW.md` issue H2.

## 4. Segment Recovery

**Configuration:** n=20000, baseline=0.10, segment deltas mobile +0.15 /
desktop −0.08, covariate correlation 0 (no clipping).

**Result:** mobile **+0.147**, desktop **−0.070**, both within the 0.02
tolerance and with the correct sign; the effect-reversal flag fires on
desktop (significant and opposite to the positive pooled effect) and not on
mobile.

## 5. Known Limitations

- The index-based O'Brien-Fleming schedule is exact only for **equally
  spaced** looks. The Lan-DeMets boundary (the default for live checks)
  removes that assumption — 5.05% under irregular spacing — but still
  assumes a fixed planned total sample size.
- Validation covers a binary conversion metric (plus one continuous CUPED
  case); heavy-tailed revenue metrics are not validated.
- Segment recovery is a single large-n check, not a repeated-simulation
  rate.
